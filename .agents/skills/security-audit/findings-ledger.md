# Security findings ledger

Issuebridge threat pack (ledger rows). Procedure: [SKILL.md](SKILL.md).

Fingerprint-only registry for Issuebridge security findings. **Public repo safe:** no attack paths, no exploit detail, no secrets. Full write-ups live in draft GitHub Security Advisories (admins only).

The **security-audit** agent must read this file before filing findings and must not re-file a concept that already has status `open`, `fixed`, `rejected`, or `accepted-risk` unless evidence shows a **regression** or material change (document why in Notes).

The **security-finding-triage** skill updates rows after stress-check.

## Evidence and status values

| Evidence    | Meaning                                                         |
| ----------- | --------------------------------------------------------------- |
| `untriaged` | Advisory claim has not been stress-checked against current code |
| `confirmed` | Repeatable safe evidence supports a reachable Medium+ finding   |
| `rejected`  | Claim is false, duplicate, out of threat model, or below Medium |

| Status          | Meaning                                                                          |
| --------------- | -------------------------------------------------------------------------------- |
| `open`          | Still in scope for triage or remediation                                         |
| `fixed`         | Remediation merged; auditor should only refile on regression                     |
| `rejected`      | Not a real Medium+ issue for Issuebridge (with rationale in triage notes / GHSA) |
| `accepted-risk` | Confirmed but explicitly deferred / accepted by maintainer                       |

## Remediation notes

- `client-secret-in-release-binary` (F1): **response complete** — fixed in code, Worker deployed, safe build shipped in Release `v0.2.1`, GitHub App client secret rotated, and user notice provided in the Release notes. Maintainer decided separate GHSA publication is not required.
- `mutable-copilot-cli` (F2): **fixed** — privileged Copilot workflows install exact version `1.0.78` from a dedicated npm lockfile with registry integrity hashes and invoke only the locked local binary.
- `mutable-third-party-release-actions` (F3): **fixed** — third-party actions in the privileged Release job are pinned to reviewed full commit SHAs, with a contract preventing mutable refs from returning.
- `pr-controlled-audit-privileged-token` (F4): **fixed** — PR scans use the short-lived job token, restore the trusted audit runtime before execution, and exclude repository-code execution tools. Merged in PR #116.
- `relative-sidecar-cwd-exec` (F5): **fixed** — implicit voice and Rewrite sidecar, model, and DLL discovery is anchored to trusted application and build roots; regression tests reject relative candidates.
- `sidecar-download-no-integrity` (F6): **fixed** — official Release fetches verify reviewed SHA-256 digests for both executable sidecar archives before extraction.
- `unprotected-tag-release-secrets`: **fixed** — Release tags are protected by an active repository ruleset, and the privileged build requires approval through the protected `release` environment.
- `agent-pipeline-plan-injection`: **fixed 2026-08-15** — Claude implement gate and plan extraction require `github-actions[bot]`; implementer spec is `verified-plan.md`. Contract tests reject a marker-only selector. Merged in PR #152; verified on `main` 2026-08-15. Previously filed on GHSA-97vr-qxvw-88gr. Current claim: GHSA-xccc-p6c7-8v7g.
- `review-agent-read-exfil-tools`: **fixed 2026-08-15** — review checkout sets `persist-credentials: false`; allowlist drops unscoped `Bash(cat:*)` / `Bash(ls:*)`. Contract tests reject the pairing. Merged in PR #153; verified on `main` 2026-08-15. Current claim: GHSA-xccc-p6c7-8v7g.
- `review-pipeline-missing-actor-gate`: **fixed** — privileged review automation requires exact allowlist or trusted automation identity checks for both the trigger actor and PR author. The original Copilot review workflow is archived and inert.
- `review-brief-untrusted-plan-source`: **fixed 2026-08-15** — review brief plan lookup requires `github-actions[bot]` and `startswith` on the marker; `jq -s add` merges paginated comment pages. Contract tests reject a marker-only selector. No Release/GHSA publication (ci-maintainer).
- `whisper-model-weak-sha1-pin`: **rejected 2026-08-15** — claimed locator and SHA-1 gate still present; the gate fails closed. Below Medium: a reviewed content pin already rejects a substituted object, and beating that pin is not a plausible attacker assumption. Distinct from `sidecar-download-no-integrity` (no pin on executable archives). Reopen if the pin is removed, skipped on the official Release fetch, or no longer a reviewed constant.
- `plan-agent-read-exfil-tools`: **fixed 2026-08-18** — planner allowlist drops unscoped `Bash(cat:*)` / `Bash(ls:*)` / `Bash(head:*)` and keeps workspace-scoped Read/Grep. Contract test rejects the pairing with the public plan-comment publish. Distinct from `review-agent-read-exfil-tools` (review workflow). No Release/GHSA publication (ci-maintainer).
- `build-root-sidecar-candidate-planting`: **rejected 2026-08-18** — claimed locator still present: voice and Rewrite candidate lists start at `env!("CARGO_MANIFEST_DIR")` and admit the first existing path. Below Medium as shipped: official Release bakes a runner crate path that does not exist on user machines, so discovery fails closed to the install root. Dev preferring the crate `binaries/` folder is the trusted build root from `relative-sidecar-cwd-exec`. Reopen if a packaged build prefers a commonly writable baked path, or if compile-time crate-root discovery is used without an existence fail-closed to the install root.
- `agent-pipeline-persisted-checkout-credentials`: **fixed 2026-08-18** — plan and implement checkouts set `persist-credentials: false`. Contract tests reject a persisted job token in those workspaces. Distinct from `plan-agent-read-exfil-tools` (allowlist pairing) and `review-agent-read-exfil-tools` (review workflow). No Release/GHSA publication (ci-maintainer).
- `agent-search-bash-unscoped-read`: **fixed 2026-09-04** — the planner and reviewer allowlists granted search-binary prefix rules. Bash allowlist entries are command-prefix rules rather than path rules, so they are runner-wide reads rather than workspace-scoped ones, in the same allowlist as a channel that publishes agent-authored content to a public comment. The two contract tests written to hold this invariant enumerated three command names, so the search binaries passed unnoticed. Fix: the planner carries no Bash rule at all and the reviewer keeps only reviewed `git` / `gh pr` read subcommands; both keep the workspace-scoped Read/Glob/Grep tools, and no brief depended on the removed rules. Both contract tests now deny by default over every Bash entry, including bare and exact-command forms, so a rule added later cannot silently inherit the channel. Residual accepted: the reviewed list still holds rules that can be pointed at a path; they are trust anchors these jobs cannot work without, and each addition must be argued in review. Supersedes the class left by `plan-agent-read-exfil-tools` and `review-agent-read-exfil-tools`: those two removed three named commands at these same two sites and stay correctly `fixed` for that fingerprint, while the general rule is enforced here. No Release/GHSA publication (ci-maintainer).
- **Backfill 2026-09-04** — the five rows above were filed by the 2026-08-23 and 2026-08-30 audits but never reached this ledger, so the registry was two audit cycles behind. Locators for all five re-verified present on `main` at the time of backfill; none has been stress-checked, so each is `untriaged` pending its own triage.
- `security-audit-persisted-checkout-credentials`: **fixed 2026-09-04** — the audit checkout now sets `persist-credentials: false`, and both base-restore steps fetch the advertised base branch only when the object is absent, matching `claude-code-review.yml`. Two contract assertions hold both properties, mirroring those that guard the other two agent workflows. Severity resolved to **medium**, matching the earlier advisory rather than the later one; the reasoning is recorded in the draft advisory, not here. Distinct from `agent-pipeline-persisted-checkout-credentials` (pipeline workflow), which holds. No Release/GHSA publication (ci-maintainer).
- `audit-agent-unscoped-read-tools`: **fixed 2026-09-04** — both audit allowlists carried the path-unrestricted read rules removed from the two sibling workflows, plus a full-mode rule that permits command execution rather than only reads, and no contract covered this workflow. Severity raised to high at triage; the reasoning is recorded in the draft advisory, not here. Fix: pr mode carries no Bash rule and full mode keeps only reviewed `git` read subcommands; the workspace-scoped Read/Glob/Grep tools already cover the procedure, and nothing in the Skill or prompt shells out. Contract tests now deny by default over both lists, resolve the PR_TOOLS reference first, and hold the agent step to that one allowlist so its consumer cannot widen it. No Release/GHSA publication (ci-maintainer).
- `nested-agent-memory-restore-gap`: **fixed 2026-09-04** — both restore steps enumerated a fixed set of root paths, so an agent memory file a pull request added below the root was neither restored nor removed. Fix: each step now enumerates candidates from the head and base trees before touching anything and applies the same restore-or-remove to them, alongside the explicit prompt-pack list. The enumeration is NUL-delimited and matched by shell case rather than a line filter, so a path git would otherwise quote is still covered. Contract tests assert the enumeration, the match arms and the iteration in both workflows, bound to the code rather than the comment beside it. Validated by extracting each shipped step verbatim and running it over scratch repositories: added, modified and deleted memory files at depth are corrected, non-ASCII and spaced paths included; ordinary files are untouched; an empty candidate set exits cleanly. Severity was medium; the reasoning is in the advisory, not here. No Release/GHSA publication (ci-maintainer).
- `rewrite-model-marker-trusted-integrity-cache`: **untriaged** — the at-rest integrity gate prefers a sibling marker file in the same user-writable directory over rehashing. `shipped-product`: any fix carries Release follow-through.
- `runtime-env-overrides-baked-oauth-endpoint`: **confirmed 2026-09-05** — the endpoint resolver returns the runtime environment value ahead of the value baked at build time, with no build-profile guard and no scheme check on what it returns, so an official build does not prefer the endpoint it shipped with. Confirmed against the shipped resolver by compiling the crate with an endpoint baked in, as a Release build has it, and observing the precedence directly: with no runtime value the baked one comes back, with one set it does not. The neighbouring resolver in the same file has the same precedence shape. The threat model names this attacker class in scope, and the crate already uses build-profile guards elsewhere. `shipped-product`: any fix carries Release follow-through, and a guard would change behaviour that the local-development docs rely on, so the direction is a maintainer decision rather than an automatic fix.
- `report-metadata-echo-public-log`: **fixed 2026-09-05** — both steps selected report lines by prefix and emitted the whole line, with no cap on line count or line length, so the adjacent comment asserting log-safe metadata was not enforced by the code. A second value derived from the report was logged unbounded in the same file. Fix: neither step emits a line of the report. Each logged key is read on its own and its value printed only when the whole value matches a closed pattern, with a placeholder otherwise; the one free-text key is reported as present or absent and never printed, and the separately derived value is bounded the same way and now read through the same extractor. The helper is duplicated across the two steps because they cannot share one. Contract tests assert the whole-value match, each closed pattern, the placeholder and the presence-only handling in both files, plus a pattern-independent rule that no read of the report may print what it matches. Shell comments, whole-line and trailing alike, are stripped before those assertions so none can pass by matching the prose beside the code. Validated by extracting the shipped step verbatim and running the shipped publisher over synthetic reports: well-formed values still print, values carrying anything extra print as unrecognized, and absent, duplicate and out-of-range keys are handled, every case exiting cleanly. Fifteen mutations across the two files are each caught by their own assertion. Severity was medium; the reasoning is in the advisory, not here. No Release/GHSA publication (ci-maintainer).
- `agent-skill-tree-restore-gap`: **confirmed 2026-09-05** — the two privileged agent jobs each restore one skill directory from the base ref, while the tracked symlink inside the runtime directory resolves to the whole skill tree; restoring the link restores the link, not what it points at. Confirmed by extracting the shipped review restore step verbatim and running it over a scratch repository: the root files and the one named directory are corrected, while a change to a sibling directory and a newly added directory both survive, exit 0, with no diagnostic. Adjacent to `nested-agent-memory-restore-gap` (fixed), which corrected the memory-file arm of the same step and does not close this one. Filed from `/security-response` triage on 2026-09-05 rather than by an audit run, so it appears in no audit report; the write-up is in the advisory, not here. `ci-maintainer`: no Release/GHSA publication.

## How to update

1. Prefer editing the matching row in place (same `concept-id`).
2. New themes from a fresh audit → add a row with evidence `untriaged`, status `open`, and the new GHSA id.
3. After triage: set both `evidence` and `status`, bump `updated` (UTC `YYYY-MM-DD`), and keep `title`/`path` fingerprint-only.
4. Never paste attack-path text, PoCs, or tokens into this file.
